# 真实设备接入说明

当前实现是四模态模拟采集闭环。`DeviceAdapter` 描述流结构、生成数据批次并提供预览；实际 SDK 与协议尚未提供，因此没有用模拟数据冒充真实硬件。

## 接入时需要的信息

| 设备 | 必要资料 |
| --- | --- |
| 摄像头 | 型号、SDK/标准接口、分辨率、帧率、像素格式、原始帧时间戳、触发能力 |
| 麦克风 | 音频接口、采样率、声道、位深、缓冲时间戳和采样位置 |
| 压力阵列 | 串口/USB/网络协议、帧长度、字节序、校验、通道数量、行列映射、量程和标定 |
| IMU | 协议/SDK、输出频率、单位、坐标系、轴顺序、姿态表示和设备时钟 |

## 实现边界

1. 在原生适配器中复用厂商 SDK 或实现协议解析，提供固定的流描述：ID、kind、dtype、shape、sample_rate、channel names、units、clock_id、标定信息。
2. 驱动在自己的线程/SDK 回调中接收数据，先校验完整性，再产生 `DataBatch`。不要在 SDK 回调中写盘、刷新 UI 或等待大队列。
3. 本版引擎按照模拟适配器的批频调度 `generate`。真实异步设备接入时，应在设备工作线程与引擎之间增加明确的批次提交接口/有界队列，保留原始时间戳，避免用模拟调度器重新标记采样时刻。
4. C/C++ SDK 可直接封装；仅提供 Python SDK 的设备适合使用独立设备进程，通过版本化元数据和批量二进制传输接入。该设备进程协议尚未实现。
5. 增加连接/配置/启动/停止/故障的生命周期处理。按设备稳定标识识别设备，不仅依赖 COM 编号或摄像头列表下标。
6. 预览只发布限频后的快照。原始数据进入录制路径，不能依赖 React 是否显示该页面。

## 设备组合与导出

界面中的组合保存选中设备 ID；每次录制将组合配置快照写入 manifest。真实设备参数接入后，应把采样率、标定版本、固件/协议版本等一并纳入配置快照。

导出器读取统一的会话与流描述，不应依赖某个设备型号。新增类型或 dtype 时同步扩展原生格式定义、Python reader、格式验证测试与 schema_version，不能只改文件扩展名。

## 接入验收

- 单设备与最大组合持续录制，核对原始序号、样本数、数据值与磁盘字节数。
- 检查缓冲有界、写盘余量、断线重连、磁盘写满与服务中断后的状态。
- 通过共同物理事件验证跨设备时间对齐；主机收到数据包的时间不能直接代表采样时间。
- 使用目标分析/训练库实际读取导出结果，检查 dtype、shape、单位、坐标系、时间索引与标定。

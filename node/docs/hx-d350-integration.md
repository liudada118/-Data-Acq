# HX-D350 双目相机接入说明

这份接入方案依据用户提供的 `HX-D350-EGO配套资料`，使用相机实际提供的 RTSP 视频流。没有实物时可以验证媒体依赖和适配器接口，不能据此认定硬件已经连接、双目同步已经验收或实时 IMU 已接入。

## 软件中的操作

1. 在 SDK 接入 Agent 中导入资料目录，让软件内配置的模型阅读 DOCX、PDF 和 Scripts/README.md，并自行生成 HX-D350 RTSP 接入草稿。平台只提供通用文档读取与媒体接口，不把现成厂商适配器作为工具返回给模型。
2. 检查草稿并执行“测试”。此步骤只检查内置媒体桥接，不打开相机，也不要求填写 IP。
3. 测试通过后安装，在传感器列表选择模型草稿中的“EGO-HX-D350 双目摄像头”（插件 ID `ego-hx-d350`）。
4. 将电脑与相机连接到同一个局域网，通过 UDEGO 的设备信息查看相机 IP。在卡片中填写 IP 或主机名并连接。适配器必须收到两路真实图像，才算连接成功。
5. 使用软件的统一开始、停止录制按钮。这里控制的是电脑侧采集，不会调用 BLE 指令控制相机 TF 卡的录制。

连接地址由 `address` 配置字段填写，例如 `192.168.1.100`；具体校验以当前模型生成的草稿为准。两路端口固定为 1254、1256，`transport` 默认 `tcp`，也可选 `udp`。不要把文档中的示例 IP 当作设备的实际 IP。

通信协议 DOCX 的 BLE FFE0 服务、FFE1 写入、FFE2 通知用于配置网络、查状态和 TF 卡录制控制；`0x07` 的 `{enable:true/false}` 控制的是设备内部录像。HTTP 接口主要用于固件、离线媒体管理。这些接口不提供本方案所需的实时 RGB 原始帧，不应该替代 RTSP 取流。

## 时间戳与同步边界

`Scripts/README.md` 说明离线 MP4 的 SVH v2 SEI 中，`exposure_start_pts_us` 才是开始曝光的 strobe 上升沿时间，可用于左右目与 IMU 对齐；`pts` 包含曝光、MIPI/ISP 等处理时间，不能直接替代曝光开始时间。字段还需要通过 `valid_flags` 判断有效。

资料没有保证当前 RTSP 流一定保留这些 SEI。本方案未提取、验证实时曝光时间，也不生成伪造的 `device_time_ns`。录制中的主机接收时间用于观察电脑端接收连续性，不能证明设备曝光同步精度。规格书的“小于 1ms”是设备指标，不是本软件这条 RTSP 接入链路的实测结果。

## 当前录制格式与容量

当前插件接口把解码后的 RGB8 图像写入原始 `MDAQBIN1` 数据文件。双路 1600×1200、30fps 时，仅图像负载约为 **345.6 MB/s（329.6 MiB/s）**，每小时约 **1.24 TB**，尚未包含记录头和其他传感器。测试安装通过不代表磁盘能够长期承受该吞吐。

本方案适合接通真实数据通道和短时验收，尚不是面向长时间双目录制的压缩视频方案。正式长时采集应增加原 H.264/H.265 压缩流保存，并独立处理预览、时间戳与异常恢复。当前适配器不会为了减少数据量而默默缩小分辨率或降低帧率；流尺寸不符应明确报错。

`src/integration/recipes/hx-d350-rtsp.mjs` 是资料核对及隔离测试使用的参考源码，不是 Agent 工具或生产预装传感器。正常接入使用内置模型实际生成的 `plugin.json`、`adapter.mjs`，随后经过测试和安装流程；源码模板自身不安装、不连接或运行厂商工具。

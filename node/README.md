# Synapse · Node 数采原型

这是独立的 **React + Node.js** 版本，先验证 SDK 接入、选设备、预览、录制和导出链路。启动时不需要 Qt、C++ 编译器或 Python。原版工程仍在上级目录。

## 启动

### 通过 Agent 接入新的 SDK（桌面版）

构建并启动桌面版：`npm run desktop:build`。已运行的旧版 Node 服务需要先停止再重启，避免桌面复用旧进程。然后在左侧打开 **SDK 接入 Agent**：

1. 打开「模型连接」，从与 shroom1.0 共用的 Shroom 模型目录选择服务商、模型，填写自己的密钥；密钥在本机加密保存。也可以选择自定义地址或手动填写其他模型 ID。
2. 「导入 SDK 文件夹」选择含文档、调用示例与运行库的目录。原目录不修改；支持直接读取 DOCX 正文、PDF 文字层和代码文本，不需要手工转成 TXT。原始二进制、图片和附件不发给模型，扫描 PDF 暂不支持 OCR。
3. 描述需求，例如“阅读这个摄像头的协议和操作指南，生成能加入传感器列表的真实采集适配器”。发送后软件内置 Agent 使用你配置的模型阅读资料、查询软件的通用媒体/原生 C ABI 能力并写出两个草稿文件；不是通过预装某款相机的适配器替代模型生成。对话回复支持标题、表格、列表和代码块。
4. 查看生成内容，点击「测试适配器」。通过后点击「安装传感器」。测试会执行本机适配代码，软件接口通过与实机验收分开显示。
5. 回到「数据采集 → 添加传感器 → 已安装 SDK」，添加卡片、填写连接参数、连接设备，再使用统一开始/停止采集。

工作台会显示“内置 Agent 生成 · 模型名称”，并绑定当前草稿修订；如果通过对话工具之外修改了草稿，会显示对应提示。安装记录也保存生成来源，方便确认适配器来自这次模型对话。

修复已有适配器时，Agent 可先读取草稿，再精确替换其中一段，避免每次重写整份文件。替换只允许 `plugin.json` 和 `adapter.mjs`，原文必须唯一匹配；修改后旧测试失效，需要重新测试再安装，生成来源仍记录为实际执行修改的 Agent。

桌面文件夹导入支持最多 **10,000 个文件、总计 8 GiB、单文件 2 GiB**，会保留厂商库、固件和示例二进制，只跳过已有规则识别的密钥、凭据及环境文件。导入先检查数量和大小，再校验并复制到本机工作区；大目录耗时取决于磁盘，界面会显示“正在校验并导入”，不会在 180 秒时误报超时。超限会指出目录、已发现的大小或数量、限制与触发文件。

导入和安装都需要目标磁盘容纳新增副本并保留至少 512 MiB 余量；空间不足会在复制前提示。副本完成校验后才发布，失败会清理本次临时副本，不覆盖原 SDK 或已安装的旧版。页面上传仍限 32 MiB；Agent 单份普通文本读取限 1 MiB、DOCX/PDF 限 16 MiB，按默认 24,000、最多 48,000 个字符分页读取，这些读取限制与二进制导入容量分别管理。

支持现成 Node SDK、原生绑定、已有桥接程序，以及软件内置的 **Koffi 3.3.7 原生 C ABI** 和受管 RTSP 解码能力。带明确 C 接口头文件与导出函数的 DLL，可由 Agent 按真实签名生成调用代码，不再必须先提供厂商 Node 绑定；驱动、系统架构和依赖库仍需匹配。纯 C++ 类/模板 ABI 或静态 `.lib` 不能直接这样调用，仍需 C 包装层或专用绑定。对于 RTSP 相机，Agent 可按文档生成配置和连接逻辑，无需另找 JS 解码库。旧工作区中的文本、DOCX/PDF 也可继续读取，前提是导入后文件未被改动。

原生库只在独立插件进程加载；“测试”可检查加载、导出和版本，不启动设备。原生代码不是权限沙箱，错误签名或失效指针仍可能使插件进程崩溃。阻塞取帧需异步调用并正确释放帧和设备句柄；原始 RGB 复制、IPC 和写盘也有开销，不能据此宣称达到原生 C++ 的采集性能。

RTSP 的测试只检查随包 FFmpeg，真正连接发生在传感器卡片点击连接后；收到完整真实帧才就绪。实际尺寸与适配器声明不符、10 秒无完整图像或断流会明确报错。当前 v1 SDK 相机保存原始 RGB `MDAQBIN1`，不会自动压缩、缩放或限帧；双路 1600×1200@30fps 约 345.6 MB/s、1.24 TB/小时，需先短时验收，长时采集还需要压缩保存和磁盘吞吐验证。系统摄像头继续沿用原有视频录制。

例如 HX-D350 的资料可直接在 Agent 中阅读；两份文档对 1254/1256 左右目的描述冲突，应先按端口命名并到机确认，不能根据离线 IMU 脚本生成虚假的实时 IMU 通道。资料依据和边界见 [HX-D350 接入说明](docs/hx-d350-integration.md)，详细接口见 [SDK 插件协议](docs/sdk-plugin-contract.md)。没有厂商设备时可以完成接口适配和安装，不能据此认定真实采集或同步精度已验证。

2026-11-11 已通过软件内置 `deepseek-v4-pro` 实际生成并修订 HX-D350 适配器，经桌面测试和安装后，传感器列表已出现“EGO-HX-D350 双目摄像头”。界面可查看 Agent 生成来源、两路 1254/1256 通道与连接参数；尚未连接实物，未进行真实视频采集、导出或性能验收。

同日 Orbbec 适配器也已由内置 Agent 生成、局部修订并安装。使用「数据采集 → 添加传感器 → 已安装 SDK → Orbbec RGB 相机」，添加卡片后可填写设备序列号，留空选第一台，再连接。当前仅请求 **RGB8 640×480@30**，实机不支持会报错；Depth/IR/IMU 尚未接入。桌面 DLL 自检和无设备错误处理已验证，尚无实机采集或性能验收；原始 RGB 约 27.6 MB/s。范围与复现说明见 [Orbbec 接入说明](docs/orbbec-integration.md)。

模型列表可点击「刷新模型列表」更新，网络不可用时使用最近缓存或随包目录。刷新只更新选项，保留填写中的地址、模型和密钥；切换服务商时不沿用其他地址的密钥。目录读取不需要密钥，实际对话仍使用你配置的模型账户。模型连接修改需要先停止运行中的 Agent 任务。若提示当前桌面不支持目录，请重启桌面软件以加载新的 preload。

复杂适配可能需要模型多轮读取资料与写代码。每次对话最多 32 轮模型/工具交互，累计上下文仍限 1 MiB；单次请求默认最多等待 10 分钟，整轮对话最多 20 分钟，期间可主动取消。整轮超时会明确提示“适配任务超过 20 分钟”并标记失败，与主动取消区分；网络读取中断与返回格式错误也会分别提示。已写入的草稿保留，可继续对话局部修订。

### Node 浏览器版

需要 Node.js 22.13+。首次安装并构建：

```powershell
cd C:\code\数采\node
npm run setup
npm start
```

之后直接运行 `npm start` 或双击本目录的 `启动Node工作站.cmd`。浏览器打开 **http://127.0.0.1:8785/**。Ctrl+C 会停止采集、排空写盘并等待导出完成。SDK 录制独立于浏览器；使用系统摄像头时必须保持采集页面打开。

本机带实验信息、标签和回放的版本运行在 **http://127.0.0.1:8788/**，使用 `npm run start:annotations` 启动。该入口复用本机 SDK 授权，使用独立的 `data/annotations/sessions` 与 `data/annotations/exports`，可通过 `ANNOTATION_PORT` 改端口。旧的 8787 服务和数据保留，已有完成录制已复制到新版目录；串口只连接到一个服务。本机原有 `npm start` 仍读取 `.env.local` 的 8787 配置，新机器未配置时使用 8785。

开发时分别在两个终端运行：

```powershell
npm run dev
npm run ui
```

React 开发地址为 `http://127.0.0.1:5180`，API 代理读取 `.env.local` 中的 `NODE_API_TARGET`，默认到 `8785`，本机原配置到 `8787`。调试新版时，在启动 UI 的终端设置 `$env:NODE_API_TARGET='http://127.0.0.1:8788'`。该读取仅限代理配置，不将授权变量传入浏览器。生产构建用 `npm run build`。

## Electron 桌面版

在项目根目录双击 `启动Electron工作站.cmd`，或在本目录运行：

```powershell
npm run desktop          # 打开已构建的 React 页面
npm run desktop:build    # 更新前端并打开窗口
npm run desktop:pack     # Windows x64 可直接运行目录
npm run desktop:dist     # Windows NSIS 安装包
node scripts/check-desktop-package.mjs  # 对实际产物跑 SDK Mock / 录制 / NPZ 验证
```

开发桌面版使用原有 8788 数据目录和本机 `.env.local`，已有健康服务则复用，没有服务则自动启动。窗口内可选择串口和系统摄像头；浏览器与 Electron 的设备选择、工作台配置分开保存，需要在新窗口重新选择。DroidCam 仍需电脑客户端先显示手机画面。

产物位于 `release/electron/`：`win-unpacked/Shroom Capture.exe` 可直接运行（需保留整个目录），`Shroom-Capture-0.1.0-x64-Setup.exe` 为安装包。安装版默认使用 8789 和 `%APPDATA%/ShroomCapture/data`，无需另装 Node；数据独立于源码版本。菜单「文件」可打开数据/配置目录。真实 SDK 授权可在该配置目录的 `.env.local` 设置 `SHROOM_LICENSE_FILE` 绝对路径，沿用现有公开 SDK 授权流程；授权和历史数据不会打进安装包。需要覆盖端口时在启动环境设置 `SYNAPSE_DESKTOP_PORT`。

退出时会先停止并保存**本窗口发起**的录制，再等待写盘和导出完成。其他页面发起的录制不会被自动停止，需回原页面保存。录制时禁止刷新窗口；保存失败会保留窗口并提示。仅由桌面启动的服务随窗口退出，复用的服务继续运行。

后台在数据排空后主动清理 Chromium 遗留的空闲/预连接，再确认退出，避免停在“正在退出”。清理发生在媒体、采集、标注及导出写盘完成之后；退出中的下载连接可能关闭，但磁盘上的录制和导出文件保留。

实现参考了 Shroom 项目的原生窗口和 NSIS 方式。运行时采用 Electron 官方的 [Node 模式](https://www.electronjs.org/docs/latest/api/environment-variables#electron_run_as_node) 保留采集子进程隔离；[媒体权限](https://www.electronjs.org/docs/latest/api/session)只授权当前本地工作站窗口。开发机需先正常安装 Electron binary；网络不可达时可以为安装命令设置 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`，安装器仍按 npm 包内 SHA-256 校验下载。

2026-11-05 验证：后端 88/88、UI 102/102、真实 Electron 生命周期 6/6、SDK Mock 全链路通过；实际打包 exe 完成 11 帧 Mock 录制、零丢弃及 NPZ 导出。桌面页面已打开并显示在线状态。尚未在 Electron 里复验真实串口及 DroidCam；安装包已生成但未安装。

## SDK 接入

0.4.0 新增手套分包协议：卡片选择串口、左右手和「分包（0.4+）」；SDK 在 921600 波特率下配对 130 字节首包与 146 字节尾包，输出 256 通道压力和 16 字节原始 IMU。旧整包设备选择「整包（兼容旧设备）」。协议选择保存在工作台，录制元数据记录所选协议；不根据串口或包类型猜左右手。

已安装并固定 **`shroom-sdk@0.4.0`**，通过公开入口 `shroom-sdk/node` 加载。依赖版本及校验信息保存在 `package-lock.json`，`npm ci` 会还原相同版本。SDK 自带模拟源的预览、录制、元数据和 NPZ 导出已通过实际 npm 包验证。

0.3.0 新增 **人体全身**和 **A 版鞋垫**。在传感器目录添加后，在展示卡片中选择串口；鞋垫需明确左右脚、12/8 bit 协议及波特率（默认 12 bit、921600）。人体展示 SDK 的 10 个物理分区、400 个映射点，同时保存 1024 原始通道。鞋垫按 112 个真实点坐标显示，保存完整 256 ADC 通道；12 bit 用 uint16 小端保存，保留 0–4095 数值，另存 40/16 字节原始 IMU。收到首个有效映射帧后才可开始录制。详见 [新传感器说明](docs/SDK_SENSORS.md)。

0.2.0 新增产品串口默认自动重连和 `onStateChange` 状态通知。工作站显式传入 `reconnect: false` 保持手动重连：连接中断后显示离线，受影响录制标记不完整，需停止保存后重新选择或连接设备。这样升级不会改变已有录制的连续性约定。

默认无需配置 SDK 路径。开发 SDK 源码时，可以通过环境变量覆盖入口：

```powershell
$env:SHROOM_SDK_PATH = 'C:\path\to\sdk-repository'
npm start
```

根目录应包含 `node/index.js`，提供 `Shroom.listPorts()`、`Shroom.mock()` 和产品连接 API。SDK 的依赖在 SDK 目录内安装。真实串口调用 SDK 自己的连接和协议解析，不在应用中重新实现其协议。

在“数据采集”页，从传感器列表把压力阵列、触觉手套等加入主展示区，再在各自卡片中选择串口并连接；手套还需选择左右手。同型号可以添加多个 SDK 卡片，分别连接不同串口；端口列表不代表设备型号识别。全部卡片就绪后可开始录制，手套会同时保存压力和原始 IMU。工作站仅提供真实设备；旧工作台和组合中的模拟项会被过滤，历史录制保留。

展示区只显示已添加的传感器。卡片配置保存在当前浏览器，刷新后恢复布局但不会自动打开串口。录制时锁定添加、移除和连接参数；移除已连接卡片会先释放它的连接。其他传感器继续运行。当前最多同时连接 8 个 SDK 实例，串口不能重复占用。

已连接卡片可在「设置」中断开，传感器、摄像头和麦克风操作一致。断开会保留卡片和连接配置，之后可重新连接；录制中需先停止并保存。

工作台保留原来的侧栏、顶部录制名称/组合与开始停止、任务栏、底部指标和日志。卡片顶部只有名称/状态小标签与「设置」、放大按钮，不使用整条标题背景；界面传感器名称省去Shroom前缀。每卡的「设置」统一管理连接、显示方式、量程及数字缩放，默认不再把缩放条放在数据上。数据自动适应标题与底部状态之间的安全区域，避免手指、手掌或其他采样点被遮挡。打开面板或翻页不会断开设备。

触觉手套在左上角名称旁用「左 / 右」标明侧别。SDK压力卡的峰值ADC合并进底部接收状态栏，点数说明收进「设置」，取消独立摘要行，把腾出的高度用于绘图区；峰值显示当前预览帧，暂停时冻结，无帧或失联时显示「—」。

未连接设备的设置默认同时展开，方便逐个选择串口、摄像头或麦克风；点击空白或其它卡片不会把它们一起关闭。可单独手动收起，设备就绪后自动收起，断开后重新展开。

多路监看仍按窗口可用空间自动排布，最多3列×2行；空间不足时使用上一屏/下一屏，所有已添加设备继续参与录制。单卡放大便于查看细节，Escape先关闭设置面板、再退出放大或专注状态；停止并保存沿用原来的录制控制。

回放页也按窗口一屏排布，播放按钮、时间轴和翻页按钮保持可见。同一设备的压力与 IMU 合在一张卡片，通过页签切换；可放大单卡查看细节。标签侧栏按需展开，设备较多或小窗口时分页，翻页不会重置回放位置或中断音视频。

点击“设置采集任务”，用一句话填写“这次要采什么”即可，项目、场景、轮次等放在“更多信息”中选填。也可选择自由采集、抓握动作或步态行走模板；模板修改下一次录制的任务名称与动作标记，保存后回到展示区再开始采集。

任务弹框统一留白，正文独立滚动，标题与底部保存按钮保持可见；小屏或较长的动作列表也可继续编辑和保存。

“动作与事件标记”是可选的时间记录：例如接触时点一下“接触”，抓握开始时点“开始抓握”，松开后点“结束抓握”。它不会自动识别动作或改变传感器数值，目的是在回放时找到发生的时刻/过程。不需要时选“自由采集”或“本次不使用标记”，照常录制和导出。录制中可打标记，修改任务和标记种类需先停止录制。

压力传感器连接并收到数据后，在卡片的「显示方式」中切换「热力图 / 2D 数字」；录制回放也支持相同切换。数字视图显示原始采样量纲和行列编号，支持滚轮缩放、拖动平移、「适应」全图和「1:1」可读字号。悬停采样点时在该点旁显示小tip（点位、已有ADC通道及原值），靠近边缘自动调整位置；移出或拖动时收起，不再出现整条读数栏，也不改变画布高度或缩放。键盘聚焦画布后可用方向键平移、+/− 缩放、Home 适应、Escape收起提示。显示模式按传感器记忆，切换只影响预览，不改变采集、标签或导出。

热力图默认使用「自动（逐帧）」量程，适合观察本帧分布；比较不同时间或设备的强度时，选择「固定」，填写相同上限后点「应用」。色带始终说明当前范围，超出上限的点会提示颜色饱和，原始值照常保留；数字视图不受量程设置影响。每路量程在当前浏览器中保存，实时与回放共用。

SDK 卡片常显最近有效帧时间和约十秒窗口内的主机接收率，暂停预览或翻页后仍更新。它区分等待首帧、观察频率、正常接收、中断及状态未知；低频设备采用保守阈值，状态读取失败不会被当作设备停发。接收正常不代表物理标定、信号质量或硬件丢包检测已经通过。

人体按十个物理分区展示数字；鞋垫按 SDK 行列映射排列，仅 112 个真实采样点有值，空白位置不是零值，悬停可查看毫米坐标。热力图仍显示鞋垫实际物理形状。12 位 ADC 保留完整整数，真实零显示 `0`，缺失或无效数据显示 `--`；未进行压力物理标定。

串口控件为下拉选择列表，显示端口号及系统设备名。添加真实 SDK 卡片并等待服务/SDK 就绪后会自动扫描一次，也可以点击旁边的刷新按钮重新检测。没有检测到串口时显示空态；已保存但当前未检测到的端口不能新建连接。各张卡片分别选择端口，不会自动连接。

真实设备连接前，由本项目 `src/capture/license.mjs` 读取 `SHROOM_LICENSE_FILE` 或 `SHROOM_LICENSE_KEY`，通过公开 `Shroom.activateLicense()` 授权。npm 包不含源码示例的 `node/license-env.js`。稳定安装标识保存在用户目录 `.shroom-sdk/device-id` 并复用；授权信息不进入前端或录制文件。

`npm start`、`npm run dev` 和启动脚本会自动加载本机 `.env.local`。本机授权文件放在忽略提交的 `.runtime/`，可通过 `SHROOM_LICENSE_FILE` 指定；测试命令不自动加载该文件。前端产品和串口参数原样传给对应公开连接接口，不自动猜测 COM 端口对应的设备型号。

手垫/手套压力保存原扫描 ADC；预览使用 SDK 映射后的矩阵。ADC 未经物理标定，不代表 kPa。手套 IMU 暂保存 SDK 给出的原始字节，未将其解释为六轴量。原始产品时间戳、序号等保留在会话附件。缺少设备时钟时使用主机接收时间并明确标记，不宣称硬件同步。

## 当前能力

- 采集界面仅展示真实设备。内置模拟适配器与 SDK Mock 仅用于开发测试，旧模拟录制仍可回放和导出。
- 安卓 / 系统摄像头：选择 Windows 可见摄像头、720p/1080p 预览、视频分块保存，可单独录制或与 SDK 组合录制。
- 独立麦克风卡片：选择 DroidCam Audio、电脑或 USB 麦克风，查看波形与电平；与摄像头、SDK 统一起停，PCM16 WAV 默认每小时或每 1 GiB 自动换段（先到者）。各段按累计样本数连续，回放自动切段，支持逐段下载；磁盘需保留足够空间。
- 传感器目录、可添加/移除的主展示卡片、卡内串口连接、多实例 SDK、设备组合、独立预览暂停、录制、历史列表、异步导出及下载。
- 实验信息、整段标签和可配置标签字典；实时瞬时事件/区间、快捷键、关联数据流、停止自动封口。标签栏可收起，传感器保持主展示区域。
- 完成录制的时间轴回放、标签定位与补标/修订。各导出格式随包包含同一版本的实验信息、标签 JSON 和 CSV，详见 [标签与回放说明](docs/ANNOTATIONS.md)。
- SDK 与采集运行在独立子进程的主线程，原生模块异常退出不会连带终止 HTTP/页面服务；格式导出使用 worker。写盘队列有条数和字节上限；溢出或设备错误使录制不完整。
- 采集异常后页面显示离线并禁用采集，旧预览停止更新；重启本地服务后恢复。React 渲染/DOM 异常显示重新加载入口。
- 原始文件沿用 `mdaqbin-v1`，后续更换采集实现可保留 HTTP 接口和录制格式。
- SDK 真实设备频率未知时，使用 `sample_rate=0`、`irregular_timestamps=true` 和逐帧接收时间。Node 导出器支持此扩展；旧版 Python reader 尚需适配后才能读取这类 SDK 会话。
- 当前 Node 导出支持 **CSV、NPZ、WAV、JSON 原始数据包**，统一 ZIP 下载。系统摄像头附原始 WebM/MP4 文件，真实麦克风附 PCM16 WAV，模拟摄像头附 PNG 和帧索引，模拟音频导出为 float32 WAV。视频和真实麦克风保持原始媒体附件，不转换成 NPZ 数组；仅摄像头或麦克风会话也可导出媒体包。
- Parquet、HDF5、MAT 和视频转码尚未实现；浏览器原生录制 MP4 的能力与通用 MP4 转码是不同功能。

数据保存在 `node/data/sessions/`，导出保存在 `node/data/exports/`，设备组合保存在浏览器独立 localStorage。重启后恢复已完成录制和导出历史；被强制终止的录制标记中断，不作为完整数据导出。

已停止且已完成收尾的「数据不完整」记录，也可以进入回放与导出。缺失/损坏的数据流独立提示，其他可读流继续显示；长 SDK 录制按游标快速定位，明确提示尚未全量校验。导出中心勾选不完整数据说明后可直接提交，无需先做全量检查。后台逐条验证，CSV/NPZ 等只转换首个坏记录之前的有效前缀，原始附件保留错误说明；包内包含原始 manifest 与缺损报告，原会话不会改成完整。分段 WAV 保留缺段的时间空隙，头部/字节数有效的旧 .wav.part 也能播放和单独下载，源文件不改名。未知媒体开始时间使用独立播放器，不猜测同步位置。

「检查异常录制」只快速读取文件头和元信息，未经逐条检查的计数、时间范围明确标记。导出在扫描前检查磁盘空间，原视频/音频和 raw 附件直接流式写入 ZIP，避免先复制一整份。空间不足会明确提示；也可以在详情单独下载原始文件到其他磁盘。仍在录制的会话需先停止保存。

## 导出包名称

ZIP 使用「录制名称_录制开始时间_格式.zip」，例如 `多模态实验 11-05_2026-11-05_16-14-00_CSV.zip`。时间按上海时区显示，同名再次导出加 `_2` 等短序号；不完整包另带「数据不完整」。默认解压文件夹使用同一名称。旧导出历史在启动时依据可用的录制元信息更新显示名，已有下载链接继续有效。

## 导出包中的传感器说明

每种 ZIP 数据包都包含 `README_数据说明.txt`（先看此文件）、`传感器文件对照表.csv`（可用 Excel / WPS 打开）和 `sensor_index.json`（供程序读取）。对照表将实际文件对应到人体、左/右手套、鞋垫、摄像头或麦克风，列出串口、设备名、数据类型与原始单位；同一手套的压力和 IMU 分开说明。文件直接命名为 `人体全身_压力.csv`、`左手手套_压力.csv`、`左手手套_IMU原始字节.csv` 等，摄像头和麦克风文件带设备名；多个同侧同类设备通过串口或稳定设备编号区分。分段音频附 `分段000001` 等原始段号。

原始录制的 manifest 和数据流 ID 保持不变；对照表同时列出原始文件名与导出文件名，`export_report.json` / `schema.json` 的 `file_mapping` 和流上的 `export_files` 记录实际包内位置。JSON 原始包读取示例会给 `readRecords` 传入 `fileMap: report.file_mapping`，正确读取中文文件名。现有依赖旧导出文件名的脚本需要按该映射查找文件。

压力文件保存原始 ADC 通道，物理点位映射见 manifest；原始 IMU 字节不会被标为已解算姿态。分段音频逐段列出文件和样本偏移，不完整包列明未包含的数据，公共 SDK 侧文件与实验/标注文件也有用途说明。

## 判断采集是否流畅

实时先看每张 SDK 卡片的窗口接收率是否稳定、最近有效帧是否持续更新，再看底部缓冲是否持续上升、软件丢弃是否增加。窗口接收率来自约 10 秒内主机接受的有效帧；不是设备标称频率。页面 2/5/10 Hz 设置控制数值和状态快照；MJPEG 插件相机使用独立二进制预览，目标最高 30 fps，只订阅当前可见画面。预览暂停或卡片隐藏会取消视频订阅，SDK 采集与原始录制继续。实际显示速度取决于设备输出、传输和解码能力。当前中断提示阈值至少 10 秒，因此几十毫秒的抖动需要录后检查逐帧接收时间间隔。

录制中的 `dropped_records` / `dropped_batches` 表示软件未写入的数据块，手套压力和 IMU 分别计数。应用保存的 sequence 是接受有效帧后生成的计数；缺口检查能发现接收后的记录缺失，不能识别设备尚未传到 SDK 的帧。真正的设备丢帧率需要可靠的设备连续序号；缺少序号时应标为未知。视频 chunks 是上传块数，不能当作视频帧数或丢帧数。

## 安卓摄像头接入

本机是 Windows 10，先把手机映射为系统摄像头，再在工作站选择。推荐从 [DroidCam 官方页面](https://droidcam.app/windows/) 安装配套 Android App 和 Windows Client（支持 Windows 10/11），按其 [USB 指引](https://droidcam.app/help/#usb) 连接；也可使用同一 Wi-Fi。USB 方式按官方指引需要手机 USB 调试和相应驱动。若手机本身提供 USB 网络摄像头模式，也可直接使用。工作站不自动安装软件或改变手机权限。

1. 先让电脑上的 DroidCam Client 显示手机画面。
2. 打开数据采集，从左侧添加“安卓 / 系统摄像头”。
3. 点击“检测”并允许当前页面访问摄像头，选择 `DroidCam Video`，连接后查看预览。支持普通 USB 摄像头；实际分辨率/帧率以设备返回值为准。若内置浏览器限制摄像头权限，请用 Chrome / Edge 打开同一地址。
4. 添加需要的 SDK 卡片并连接，点击开始采集。停止时等待最后一块视频上传完成，在会话详情下载视频，或导出包含视频和传感器数据的 ZIP。

如果 DroidCam Client 已有画面，但采集页只显示 ToDesk Camera：确认使用当前工作站地址（本机标签/SDK 0.3.0 版为 `http://127.0.0.1:8788/`）。Chrome 若提示“重新加载此页面”，先刷新使权限设置生效。工作站会先枚举已授权的设备，显示检测到的名称；在卡片内明确选择 `DroidCam Video` 再连接，不依赖浏览器默认摄像头。已连接 ToDesk 时需先断开该卡片，才能重新选择设备。设备插拔、页面重新获得焦点、回到页面或支持的权限变化事件会被动更新列表，不自动打开或切换正在使用的摄像头；首次授权仍由“检测”按钮发起。

PC 浏览器通过 `getUserMedia({audio:false})` 获取画面，`<video>` 直接预览；`MediaRecorder` 优先选择受支持的 WebM，必要时选择 MP4，不经 Canvas/JPEG/base64 逐帧传输。默认请求 720p/30fps，录制约 4Mbps，实际编码和画质依设备/浏览器而定。声音通过独立麦克风卡片选择，不自动混入视频文件。

每路约 1 秒产生一块，上传队列有 32 块/64MiB 上限，服务端单块上限 16MiB、按序流式写盘并在完成时刷盘。`streams` 保存传感器原始数据，`media_streams` 与 `assets` 保存视频及时间元数据。块数不代表视频帧数。浏览器时间线与服务端接收时间用于关联会话，不保证曝光时间或硬件同步。

录制时保持本页面打开，先点击停止并保存再刷新或关闭。摄像头断开、页面失联、编码/上传失败、未收到数据或未正常完成均标记为不完整，已写入的部分文件保留；不会用模拟画面替代真实设备。摄像头租约凭据仅保存在页面内存，刷新后需重新连接。

含摄像头的录制应在开始录制的页面点击“停止并保存”，使最后一段视频上传完成后再结束会话。另一个页面会提示返回启动页，不会替它直接结束编码器。若原页面已关闭，待摄像头连接失效后，可在当前页面停止并保留残余录制，未完成的视频会标记为不完整。重复点击或上一段迟到的停止请求会校验目标会话，避免影响下一段录制。

## 独立麦克风与同一台安卓手机

1. 在 DroidCam Client 启用 **Enable Audio**，并允许手机应用使用麦克风；手机声音需要作为 Windows 输入设备 `DroidCam Audio` 出现。详见 [DroidCam 官方音频说明](https://droidcam.app/help/)。
2. 在传感器列表添加“麦克风”，点击“检测”并允许麦克风访问，在卡片内明确选择 `DroidCam Audio` 后连接。也可选择电脑或 USB 麦克风；不会按名称自动切换设备。
3. 同一台手机的画面在摄像头卡片选择 `DroidCam Video`，声音在麦克风卡片选择 `DroidCam Audio`。两张卡片可独立连接，麦克风卡片显示输入波形与电平，不将声音回放到扬声器。
4. 点击统一的“开始采集”；“停止并保存”会等待两种媒体收齐尾块，再结束传感器录制。录制记录详情提供每路“下载 WAV”，回放页可直接听音频，所有导出 ZIP 同样附带 WAV。不需要视频时，仅添加麦克风也可录制。

音频使用 AudioWorklet 采集为单声道、16 bit 小端 PCM，采样率以音频引擎实际值保存并显示（浏览器可能对输入重采样）。每约 250ms 上传一块，主线程和音频线程均限制积压，后端写标准 RIFF/WAVE 文件；停止后按实际样本数量计算音频长度，验证累计确认字节并刷盘。单个 WAV 的 PCM 数据受标准 RIFF 约 4GiB 限制，超限会停止并保留不完整记录，不覆盖旧数据。当前不提供 RF64 或自动分卷。

摄像头与麦克风共用会话，但独立文件、独立设备选择；统一按钮不代表硬件同步。回放用保存的开始时间估计对齐。暂停预览、收起参数、翻页或切换界面不会停止音频录制；实际录制页关闭、设备断开、音频引擎暂停或上传失败会保留已有数据并标记不完整。在另一页面不能正常收尾仍由原页面采集的音视频，应回到开始录制的页面停止。Electron 正常关闭会先排空本窗口拥有的录制。

麦克风“已连接”表示输入设备打开成功，不等于已有声音。可见预览连续约 5 秒低于 −60 dBFS 时，卡片提示对麦克风说话并检查 DroidCam 的 Enable Audio；声音恢复后提示自动消失。音频引擎暂停/系统中断/关闭、轨道禁用或暂时静音会显示各自状态。安静提示不会阻止正常录制，也不改变录音增益或打开扬声器；暂停预览、翻页隐藏、切到后台期间不累计静音时间。

手机有画面但音频一直平直时，在**电脑端 DroidCam Client** 下方 Sources 中双击手机源，或选择手机后点击画面下方、Filters 左侧的 **Properties**，检查 **Enable Audio**。该选项是 DroidCam 手机源的音频传输设置，数采页面的设备下拉列表无法替它开启；手机侧还需要麦克风权限。不要因为视频正常就假定音频也已启用。

`CaptureEngine` 是替换边界：设备枚举、状态、预览、start/stop 及 SDK 连接方法由 HTTP 层统一调用。将来可以把这个实现改为 C++/Rust 进程客户端，而保留上层页面。当前验证目标是功能链路，真实吞吐、丢包和同步误差仍需实际设备压测。

## 左侧音视频与时间连续性报告

摄像头与麦克风集中在展示区最左侧：上方大画面，下方紧凑音频；右侧显示压力与 IMU。设备选择、连接仍各自独立，可使用同一台手机的 DroidCam Video/Audio；统一开始和停止录制，音频仍单独保存为 WAV。回放采用相同布局，翻页或放大不会重建媒体节点。窄窗口自动上下排列。

摄像头与麦克风作为一个组合放在一屏内：拖动两张卡之间的分隔条调整上下高度，麦克风增高时摄像头相应缩短；拖动音视频栏右侧分隔条，同时调整两张卡的宽度。间距和分隔条已计入展示区尺寸，短窗口会按比例压缩，拖动不会把页面撑大；麦克风设置单行展示设备、检测和连接，长说明与完整错误从问号打开，卡片过矮时设置也改用弹窗，避免内部滚动和裁切，摄像头设置与回放音频详情仍可在卡内滚动。

压力、IMU 等传感器卡片可单独调整宽高：宽度不超过当前列，高度可拖动到展示区底部；点击“纵向铺满”可保持本列宽度、跨上下行占满一屏高度，“恢复高度”保留宽度。高卡占一列，其他卡填入剩余位置，放不下时分页，不会重叠或撑大页面；当前调整的卡片会保持可见。底部“还原”恢复整张卡，“恢复卡片大小”同时恢复本页媒体比例和传感器尺寸。方向键微调，Shift 加速，Home 还原。

拖动传感器标题栏空白处或“移动”按钮，放到另一张卡上会直接交换双方位置，目标提示“松开交换位置”；放到空格只移动当前卡，放回自身不改变布局。纵向铺满卡覆盖的上下行都可作为目标，交换后各自保持原尺寸，必要时其他卡片自动避让，不会重叠或撑大页面。也可点击“移动”使用方向按钮和“最左/最右”，或聚焦移动按钮后用方向键逐格移动、Home / End 移到两侧，落点已有卡片时同样交换；Escape 取消，菜单“恢复”还原自动位置。双方位置按采集页面和每条录制分别保存，刷新后仍保持交换结果，原有位置偏好继续兼容；移动不会重连设备或改变录制数据。

媒体比例按采集页面和每条录制分别记忆，使用 `shroom:media-layout:v2:<scope>`（scope 为 `live` 或 `replay:<sessionId>`，存储时编码）。旧版逐张媒体卡的尺寸不再读取；传感器仍按各卡 ID 保存，纵向铺满状态会随窗口高度重算，刷新后继续保持。缩小窗口只约束显示，放大后恢复偏好；调整布局不会重新连接设备或改变录制数据。

在“录制记录”或回放顶部点“时间连续性”，再点“开始检查”。默认 100ms 是可调整的帧间隔预警阈值。报告按左右手、压力、IMU 展示接收率、间隔分位数、最长间隔、超阈次数、应用序号缺口及异常位置；定位按钮可跳转回放。检查支持不完整录制，损坏流独立显示可读部分；大录制可取消，开始新采集会终止历史扫描。

报告只读原文件，缓存保存在服务内存中，重启后重新生成；可单独下载很小的 JSON 报告。分位数使用固定对数直方图近似，不是逐项精确排序。报告同时显示平均间隔和超阈占比；超过阈值的次数不是丢帧数。227Hz 约为平均4.41ms一条，不表示每条记录等间隔到达；人体97Hz平均约10.3ms，用6ms阈值会大量超阈。软件记录与主机接收时间无法证明硬件零丢帧；音频检查限于分段/文件头，视频尚未逐帧分析，跨设备同步与信号质量标为未验证。

# 实验信息、标签与回放

工作站的标签附着于一次录制，使用相对该会话起点的时间。原始传感器文件保持不变；实验信息和标注修订保存在同目录的 `annotations.json`。

## 使用流程

1. 采集前打开实验信息，填写项目、任务、对象编号、场景、轮次、备注和整段标签。
2. 设置本次实验的标签字典：名称、颜色、快捷键，以及瞬时事件或时间区间。
3. 开始录制后，在标签栏点击标签或使用快捷键。瞬时事件产生一个时间点，区间需要开始和结束两次操作。正在输入文字时不会触发标签快捷键。
4. 停止录制后，从录制记录进入“回放与标注”，拖动时间轴检查各路数据，补充或修正标签的时间、范围和备注。
5. 从导出中心导出，ZIP 同时包含实验信息、标签 JSON/CSV 和所选格式的数据。

标签范围为空表示整段多模态会话，也可以指定一个或多个数据流。例如“抓握”可标记整个会话，“画面遮挡”可以只标记摄像头。

## 时间与精度

- `start_ns`、`end_ns` 是相对会话起点的纳秒十进制字符串。JSON 中不使用浮点数保存纳秒整数。
- 瞬时事件的起止时间相同；尚未结束的区间 `end_ns` 为 `null`。
- 实时打点在采集进程处理操作时读取单调时钟。它包含操作反应和传输延迟，不能代表硬件触发时刻；需要时可在回放中校正。
- 录制正常停止时，未结束的区间封口到结束时间，并保留自动封口记录。异常恢复的封口会标记恢复原因。
- 回放使用已保存的原始时间戳定位附近数据，不更改或重采样原始记录。界面刷新频率不是设备采样率。
- 设备接收时间、浏览器编码视频时间和真实采样/曝光时间不是同一概念。目前没有硬件同步保证。

## 数据与修订

`annotations.json` 保存以下内容：

| 字段 | 含义 |
| --- | --- |
| `schema_version` / `session_id` | 文件格式版本、所属会话 |
| `revision` | 用于并发修改校验的递增版本 |
| `experiment` | 项目、任务、对象编号、场景、轮次、备注、整段标签 |
| `labels` | 本会话标签字典 |
| `annotations` | 当前有效的瞬时事件和区间 |
| `history` | 新增、修改、删除、自动封口等修订记录 |

每条标注保留自身 ID、标签 ID 与名称/颜色快照、起止时间、关联流、备注、来源及创建/修改时间。会话 manifest 中的实验信息和字典是开始录制时的快照；后续修订以标注文件为准。

保存时带上读取到的 `revision`。若其他页面已经修改，会返回冲突，界面刷新后由用户重新操作，避免静默覆盖。服务端校验标签、数据流、时间范围及文件路径，并原子替换标注文件。

旧录制没有标注文件时仍可查看、补标和导出，不需要改写原始数据。

## API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/sessions/start` | 原有参数之外可传 `experiment` 和 `labels` |
| GET | `/api/sessions/:id/annotations` | 获取实验信息、字典、标注与修订 |
| POST | `/api/sessions/:id/annotations` | 带 `revision`，执行 `mark`、`begin`、`end`、`upsert` 或 `delete` |
| POST | `/api/sessions/:id/context` | 录制后修改实验信息或标签字典 |
| GET | `/api/sessions/:id/replay?time_s=…` | 查询指定相对时间的已保存数据 |

实时 `mark`、`begin`、`end` 使用采集端时钟，不接受浏览器用预览刷新时间替代。录制后的 `upsert` 带准确的起止时间，`delete` 带标注 ID；修改均保留记录。

## 导出

各格式的 ZIP 都附带同一修订的 `annotations.json`、`annotations.csv` 和 `experiment.json`。导出报告标明标签修订及时间基准；后续修改标签需创建新导出任务，已生成的包不会随页面修改。

JSON 保留精确时间、完整字典和修订记录，适合程序处理；CSV 方便查看和分析。包含原始视频的会话继续附带原生视频文件，不伪造逐帧采样时间。
